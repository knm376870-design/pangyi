# 输入稳定性回归

## 修复场景

- 中文模式下，小键盘 1–9、F1–F11 等虚拟键码曾被当成 ASCII 小写字母。例如小键盘 1 的 `0x61` 被认成 `a`，F5 的 `0x74` 被认成 `t`。现在只有 Windows 的 `VK_A..VK_Z` 能开始或继续拼音，功能键和小键盘交给应用处理。
- 宿主主动终止组合时，旧代码只释放组合引用，保留拼音、候选和句子缓冲。现在收到当前组合的终止通知时一起清空状态、隐藏候选窗；旧组合的通知不会取消新输入。
- 更新或结束组合时，旧代码在持有组合互斥锁的情况下调用 `GetRange`、`SetText`、`EndComposition`。宿主若同步回调并再次访问组合，就可能卡死。现在先取出或复制组合引用，释放锁后再调用这些接口。
- 候选窗曾用主屏尺寸裁剪所有坐标，副屏上的候选可能跳回主屏或被截断。现在取光标所在显示器的工作区，保留负坐标、避开任务栏，并在边缘调整位置。
- 俄语侧上屏和逐词翻译曾按汉字重新反查，可能借用同形多音字的另一条释义。现在提交时保存当前候选的汉字与释义，空释义保留中文，空格、数字、标点和大写字母路径均使用同一份候选内容。
- 横排候选的鼠标点选曾使用竖排行号，点后面的词也可能选中第一项。现在按每个候选的实际宽度判断，页首说明和下方释义区域不触发选词。
- 候选项不再显示拼音注音：竖排只保留序号、中文和俄语三列，横排下方只保留当前项的俄语释义。释义区域按整页测量，切换候选不会裁掉译文，整页无释义时不留空注释行。顶行仍显示正在键入的字母，供退格与改字参考。
- 去掉注音列后，俄语列的绘制与点击边界同步左移；中文侧的测试矩形以俄语列为右边界，短词不会误点到俄语侧。
- 翻页原来只切换候选数据，没有立即重画和调整窗口大小。现在翻页与跨页移动后按原光标锚点刷新窗口，显示与实际选词保持一致；整句模式的提示也跟随选中项更新。
- 无匹配候选时，Tab 原来先被接管、随后又报告未处理，导致应用收不到按键；现在直接交给应用。回车或空格则提交原始字母并结束组合，避免下一次输入覆盖未结束的旧组合。
- 候选窗统一使用实际显示个数计算布局和点选。屏幕边缘裁剪后的窗口外、隐藏候选、空俄语释义和页码区域不触发选词；导出的点选矩形也裁剪到可见范围。

## 自动验证

Windows + Rust，在 `ime` 目录运行：

```powershell
cargo test --lib
cargo build --release --lib
cargo check --lib --target i686-pc-windows-gnu
cargo run --release --bin quality_test
```

依赖已缓存时可加 `--offline`。32 位检查需要安装相应 Rust target。
若 Windows GNU 链接器在含中文的输出路径中报告找不到对象文件，可把 `CARGO_TARGET_DIR` 指向有写权限的纯英文路径后重试。

`src/stability_tests.rs` 保留以下七项稳定性回归：

1. 无拼音和有拼音时，小键盘、F1–F24 及扩展键码都不被字母判定截获。
2. A–Z 仍能输入拼音，英文模式下放行。
3. 功能键和小键盘的按键处理不会改变已有拼音。
4. 宿主终止当前组合后清空拼音、两份候选池、候选窗内容、页码、定位和句子缓冲。
5. 旧组合的终止通知不影响新组合及其拼音。
6. 取消组合时允许同步回调，且主动取消的回调不清除已提交的句子缓冲。
7. 更新组合时在锁外调用 COM 接口。

COM 测试对象会在接口入口检查组合锁是否可取得，并模拟同步终止回调；旧实现会报告失败，测试不会故意把执行线程挂死。

另有四项候选释义回归：选中读音的释义、空释义回退中文、逐词翻译与俄语侧优先级、清理候选池后仍保留所选条目。`cand::placement_tests` 包含七项工作区定位测试（右侧/左侧/上方副屏、各边任务栏、小工作区等）和四项横排点击测试（各词、说明区、边界和命中矩形）。这些几何测试使用明确的屏幕与点击坐标，无需真实副屏或鼠标操作。

RC4 另增九项回归：三项检查空候选的 Tab 放行、回车/空格原始文本提交及翻页选择状态；六项检查显示个数上限、横竖裁剪、短/空俄语释义、隐藏行和页脚命中范围。原始文本提交测试通过内存中的假 `ITfContext` / `ITfRange` 执行真实编辑会话，核对文字、组合结束次数、锁释放，以及句子缓冲和自学习文件不被改变。

多显示器定位采用 [Microsoft 的工作区定位规则](https://learn.microsoft.com/en-us/windows/win32/gdi/positioning-objects-on-multiple-display-monitors)，通过 `MonitorFromPoint` 与 `GetMonitorInfoW` 获取屏幕工作区。

## 本次结果与验证边界

2026-10-16，Rust 1.99.0 / Windows GNU：`4.6.1-rc.4` 的 31 项测试全部通过。64 位和 32 位 Release DLL 均已实际链接并加载，每种架构的 55 组按键测试/处理回调和 COM 创建、释放、卸载计数检查全部通过。此前现有候选基准的 60 组拼音中，59 组首选命中，全部进入前九；`jingli` 的「经理」位于第二位。本轮未修改词库内容与候选排序算法。

本地测试安装包 `旁译-v4.6.1-rc.4.exe` 的 SHA256 为 `12df582ca00f4988cdd18507d02f5805d09d9fade806e582d1098850ec07069b`。安装程序的版本、中文说明、内嵌 DLL 和七档图标已核对。

`tools/build_release.ps1` 在生成安装包前运行 `stability_probe`，直接加载每个架构的新 DLL、创建其真实 COM 服务并检查按键回调。脚本还检查 DLL/EXE 的 PE 架构、安装程序版本与中文资源，并生成 SHA256 校验文件。图标已随源码保存，构建不再依赖旧安装包。

安装包已额外核对内嵌的两个 DLL 与本次构建的文件完全一致，七档图标资源与源 ICO 的图片数据一致。资源脚本使用数字 ID 1 定义版本信息，避免 LLVM 资源工具把 `VS_VERSION_INFO` 当成名称、导致 Windows 无法读取版本。

这些测试验证按键处理、编辑回调和二进制打包，不会安装输入法、修改系统注册或向其他窗口发送按键。本轮另行安装了 RC4，并核对版本文件、卸载版本、桌面入口和 32/64 位注册目标 DLL：文件哈希均与本次安装包一致。已加载旧 DLL 的应用需重新打开；注销后重新登录可让当前会话完整加载新版本。

记事本、浏览器、Word 等应用的真实输入、焦点切换与候选窗显示仍需另行验收；本轮桌面自动化工具初始化被运行环境的文件权限限制阻断，因此保留候选版本标记和草稿 PR。
